# 迷雾迷径 · 阶段 2 可玩版本

回合制 · 六边形网格迷宫探索 Roguelite。

本仓库当前实现的是《迷雾迷径》设计文档的**阶段 2**：在一座 BSP 生成的纯黑迷宫里，
你靠掷骰获得移动力、靠「探听」获取相邻格信息，绕开怪物、陷阱与墙，穿过功能房间，
在出口房击败守卫后抵达出口即通关。

完整设计见 [`docs/superpowers/specs/2026-11-04-hex-maze-roguelite-design.md`](docs/superpowers/specs/2026-11-04-hex-maze-roguelite-design.md)。

## 运行

```bash
npm install
npm run dev        # http://127.0.0.1:5180
```

| 命令 | 作用 |
|---|---|
| `npm run dev` | 启动开发服务器（端口固定 5180，避免与其他项目冲突） |
| `npm run build` | `tsc --noEmit` 类型门禁 + Vite 产物构建到 `dist/` |
| `npm run typecheck` | 只跑类型检查 |
| `npm test` | Vitest 单测（规则层 + store + 渲染模型 + 组件） |
| `npm run test:e2e` | Playwright 冒烟用例（独立门禁，不进 `npm test`） |

## 阶段 1–2 已实现

- **实心六边形石板**：地板是满铺的实心正六边形，不描边，相邻格并成一块连续石面；每格带固定色差与细板缝。
  所有石面共用一套以玩家为心的光照渐变，越远越暗。
- **地块厚度**：地板簇的外缘向下露出侧面（只有朝向观察者的两条边会露），外缘再压一圈暗角，整块地形读起来是浮在黑暗里的石台。
- **墙**：墙不占整格，而是画在地板格与墙格共享的那条边上；边脊加高到能夹住通道，墙格本身保持纯黑。
- **迷雾**：未踏足的格子完全不可见（纯黑），踏足过永久可见。
- **探听**：消耗 1 移动点，每回合限 2 次（探查术可临时 +3），返回相邻格三态（有墙 / 通路（安静）/ 通路（有异响））。
  「有异响」表示该格或更深处有陷阱，是阶段 1 的主要预警手段。
- **可落脚高亮**：站在一格时，周围「已知可站立」（已踏足 或 探听到是通路）的邻居会被亮色描边 + 中心点标出，
  并在与你共用的那条边上画出指向它的箭头；未知邻居不画任何东西，不泄露。
- **回合与骰子**：每回合掷 3d6，移动点 = 未预留骰子的面值之和 − 已花点；出牌会锁住一颗骰子。
- **移动与胜利**：沿相邻格走，踏上出口即胜利。
- **关卡生成**：BSP 切出 9 个房间（46×30），轴向走廊连通，房间内做墙增广、拆掉死路、拆约 18% 的候选墙造环；
  起点固定在左边缘、出口在右边缘。同一种子完全可复现，1000 个种子的不变量校验全绿。
- **房间系统（阶段 2）**：起点房 / 出口房 / 奇遇房 ×3 / 宝箱房 / 休整房 / 战斗房 / 陷阱房。
  宝箱房开箱、休整房回血并锁定一张卡，每房只结算一次；踏入战斗房会立刻惊动房内怪物。
- **特殊地形（阶段 2）**：乱石 / 水渍 / 风口，落点立即清除该格与相邻格的气味（含本步气味）；
  只影响气味，不改变通行性。
- **奇遇房 Q&A（阶段 2）**：内置 48 道可判对错的题目，同步出题、无网络；
  答对回血 / 抽卡 / 临时 buff，答错扣 15% 最大 HP 或一张卡（手牌 ≤3 或休整锁定则改扣血）；
  每题可花一张卡换一条不含答案的线索；连答 3 题额外抽 2 张普通卡。
  题面面板打开时会接管键盘（T/F/H/Esc），不会误触移动或结束回合。
- **守卫 Boss（阶段 2）**：守卫守在出口房，玩家进入或被攻击才觉醒；HP 降到 2/3、1/3 进入
  召唤阶段与 AOE 阶段（只进不退）。召唤 2 只嗅犬并自愈 30，AOE 半径 2、伤害 18，意图提前一回合公开。
  **守卫存活时踏上出口不判胜**，击杀后才开放出口。
- **陷阱**：踩中受 5 点伤害，并随机附加流血（3 伤 × 3 回合）或中毒（2 伤 × 3 回合）；
  中毒期间治疗减半，「止血」可以清除。每个陷阱都保证绕得开。
- **怪物与追踪（阶段 1）**：嗅犬 / 石卫 / 游魂 / 蛛巢按三态规则行动（游荡 / 警觉 / 追击），循气味移动；
  意图预掷并公开（移动格数 / 伤害 / 搜索 / 定身），玩家可以据此规划。
  首次被发现时有一回合预警（头顶「!」）；驱散后 2 回合不再感知，定身封锁当回合的行动与感知；
  攻击意图在结算时复查距离，退开即可让攻击落空。蛛巢每回合最多布 2 个陷阱。
- **卡牌与战斗（阶段 1）**：15 张普通卡，打出需要一颗点数足够的骰子；
  近战消耗 1 移动点造成 5 点伤害，怪物没死就会挡住去路；击杀必掉一张非初始牌（手牌上限 15）。
- **平衡模拟**：`npm run balance` 驱动真实的 `createGame` + `reduceGame` 跑无头模拟（策略只产 intent），
  含迷雾受限策略与承伤/卡牌使用拆分；数据与结论见 [`docs/balance/phase2-content.md`](docs/balance/phase2-content.md)。
- **反馈演出**：规则层每次状态转移都会产出一串**演出事件**（移动 / 攻击 / 掉血 / 死亡 / 踩陷阱），
  表现层把它们排成时间轴逐条演出，因此玩家能看清「我走了哪一格」「谁打了我」「打掉了多少血」：
  - 玩家走位是插值的，提灯跟着走，地面不再整片闪一下；镜头带一点迟滞，移动方向读得出来。
  - 怪物行动**排队演出**：每只怪依次行动，不会同时结算。
  - 怪物头顶有血条，命中有闪白与伤害数字，死亡时消散。
  - 挨打时玩家闪白、镜头轻震、顶栏体力条带残影；踩中陷阱有飘字与轻震。

仍**不做**：LLM 出题（题库为内置静态数据，`store.injectQuestions()` 是外部注入缝）、
商店 / 祭坛 / 碎片经济 / 精良与史诗卡池 / 局外循环、音效、标题与结算画面。

|---|---|

## 架构

```
UI 事件 → dispatch(intent) → Zustand store → rules/ 纯函数 reducer → 新 state + 演出事件
                                                              ↓
                                       render/ 演出层（事件 → 时间轴 → 逐帧表现）
```

- `src/rules/`：纯函数、零 DOM 依赖、随机性可注入（`GameState.rngState`），可在 Node 下独立运行与单测。
  每次状态转移会产出一串演出事件（`GameState.events`），描述「发生了什么」而不描述「怎么演」。
- `src/state/`：Zustand store，是唯一调用 `reduceGame` 的地方；不镜像派生值。
- `src/render/`：只读 state，不含任何规则判断；外观分类走 `rules/fog` 的查询函数。
  `presentation.ts` 把演出事件排成时间轴，逐帧产出位置、血量、伤害数字等表现状态。
- `src/ui/`：只派发意图，不直接改状态。画布由 `requestAnimationFrame` 循环驱动。
- `src/core/`、`src/sim/`：可序列化的随机数状态机、意图时间线、快照哈希与回放确定性校验。

## 测试

- 规则层：网格几何与寻路、关卡生成（1000 个种子 fuzz：连通、填充率、环路、最短路径、陷阱可绕开）、探听与地形 100% 一致、骰子分配 10368 种组合穷举、reducer 纯度与确定性。
- 玩法链路：踩陷阱掉血 / 上状态 / 消耗陷阱、蛛巢布陷阱上限、击杀掉落与手牌上限、疾行 / 探查术 / 铁壁姿态的数值与生命周期。
- 怪物时序：定身不感知、驱散 2 回合失智、屏息不泄露位置、攻击落空、预警回合不行动、eager 守卫跳过预警。
- 守卫：未激活只守原位、被攻击/进房唤醒、阶段阈值只进不退、阶段 2 一次性召唤与回血、AOE 走减伤管线、守卫未死不判胜。
- 房间与奇遇：每房只结算一次、地形清味含本步气味、战斗房强制追击、题目 schema 过滤、提示扣卡、连答 3 题奖励、答题态不被自动结束回合打断。
- 事件流：移动 / 攻击 / 死亡 / 踩陷阱各自产出正确且有序的演出事件；被拒绝的行动不产生事件。
- 演出层：走位是插值而非瞬移、怪物行动排队、体力条渐变、看不见的怪不演出。
- 组件层：骰子盘、探听按钮的禁用理由、快捷键派发。
- 回放：同种子同操作序列必须逐步哈希一致，改操作必须分叉。

## E2E 说明

`npm run test:e2e` 使用**系统已安装的 Chrome**（`channel: 'chrome'`），
不执行 `npx playwright install`，因此不会下载浏览器。若本机没有 Chrome，请改用 Edge：

```ts
// playwright.config.ts
channel: 'msedge',
```

## 已知取舍

| 项 | 阶段 1 的选择 |
|---|---|
| 网格拓扑 | 逻辑与视觉统一为 pointy-top 六边形，轴向坐标六向邻接，相邻格共享整条边 |
| 墙的呈现 | 墙以共享边上的高边脊呈现而非整格；可见地板格一律按真实地形描墙脊，因此**探听的信息价值下降**（只剩通路 / 异响与可落脚标记）。要收回这个取舍，把渲染模型里墙边的取值改为「仅当邻格已知为墙」即可，不影响其余渲染逻辑 |
| 美术方向 | 暖色石板 + 提灯光源（three.js 2.5D 已落地）：六棱柱石台带法线凹凸与厚度，提灯区亮、记忆区恒暗；墙的亮度随提灯距离变化，远处墙保持暗色 |
| 移动点上限 | 不设上限，严格按设计文档 §3.2 的字面公式（疾行在此之上 +1/回合） |
| 锁骰 | 出牌必须锁一颗点数足够的骰子；预留但不使用的骰子不计入移动点，随时可取消 |
| 探听结果 | 永久保留，不随回合过期 |
| 地图尺度 | 34×24、7 个房间；死路只统计不拦截（零死路属阶段 2 验收） |
| 胜利条件 | 踏上出口格即胜（守卫 Boss 属阶段 2） |
