# 迷雾迷径 · 阶段 0 可玩骨架

回合制 · 六边形网格迷宫探索 Roguelite。

本仓库当前实现的是《迷雾迷径》设计文档的**阶段 0 · 可玩骨架**：在一座纯黑迷宫里，
你靠掷骰获得移动力、靠「探听」获取相邻格信息，抵达对侧出口即通关。

完整设计见 [`docs/superpowers/specs/2026-11-04-hex-maze-roguelite-design.md`](docs/superpowers/specs/2026-11-04-hex-maze-roguelite-design.md)。

## 运行

```bash
npm install
npm run dev        # http://127.0.0.1:5180
```

| 命令 | 作用 |
|---|---|
| `npm run dev` | 启动开发服务器（端口固定 5180，避免与其他项目冲突） |
| `npm run build` | `tsc --noEmit` 类型门禁 + Vite 产物构建到 `dist/` |
| `npm run typecheck` | 只跑类型检查 |
| `npm test` | Vitest 单测（规则层 + store + 渲染模型 + 组件） |
| `npm run test:e2e` | Playwright 冒烟用例（独立门禁，不进 `npm test`） |

## 阶段 0 已实现

- **六边形地板与墙边描边**：地板是满铺的正六边形；墙不占整格，而是画在地板格与墙格共享的那条边上（实心粗线 + 内侧渐变阴影），墙格本身保持纯黑。
- **迷雾**：未踏足的格子完全不可见（纯黑），踏足过永久可见。
- **探听**：消耗 1 移动点，每回合限 2 次，返回相邻格三态（有墙 / 通路（安静）/ 通路（有异响））。
  阶段 0 没有陷阱，因此「有异响」在数学上不可能出现——规则层不会编造不存在的异常。
- **可落脚高亮**：站在一格时，周围「已知可站立」（已踏足 或 探听到是通路）的邻居会被亮色描边 + 中心点标出，
  并在与你共用的那条边上画出指向它的箭头；未知邻居不画任何东西，不泄露。
- **回合与骰子**：每回合掷 3d6，移动点 = 未预留骰子的面值之和 − 已花点；预留槽在阶段 0 无用途，
  但把「骰子分配」的数据结构与交互提前落地，阶段 1 加卡牌时只需新增一个消耗槽。
- **移动**：沿相邻格走，踏上出口即胜利。
- **关卡生成**：带东向偏置的随机自避行走生成主走廊 + 3 条支路 + 2 条捷径环，起点在左、出口在右，
  同一种子完全可复现。
- **怪物与追踪（阶段 1）**：4 种怪物按三态规则行动（游荡 / 警觉 / 追击），循气味移动；
  意图预掷并公开（移动格数 / 伤害 / 搜索 / 定身），玩家可以据此规划。
- **卡牌与战斗（阶段 1）**：15 张普通卡，打出需要一颗点数足够的骰子（锁骰终于有用）；
  近战消耗 1 移动点造成 5 点伤害，怪物没死就会挡住去路。
- **平衡模拟**：`npm run balance` 用正式规则层跑无头模拟，
  数据与结论见 [`docs/balance/phase1-mobility.md`](docs/balance/phase1-mobility.md)。

仍**不做**：房间与奇遇、LLM 出题、碎片与商店、局外系统、音效与特效。

## 架构

```
UI 事件 → dispatch(intent) → Zustand store → rules/ 纯函数 reducer → 新 state
                                                              ↓
                                                     render/ 只读重绘
```

- `src/rules/`：纯函数、零 DOM 依赖、随机性可注入（`GameState.rngState`），可在 Node 下独立运行与单测。
- `src/state/`：Zustand store，是唯一调用 `reduceGame` 的地方；不镜像派生值。
- `src/render/`：只读 state，不含任何规则判断；外观分类走 `rules/fog` 的查询函数。
- `src/ui/`：只派发意图，不直接改状态。
- `src/core/`、`src/sim/`：可序列化的随机数状态机、意图时间线、快照哈希与回放确定性校验。

## 测试

- 规则层：网格几何与寻路、关卡生成（200 个种子 fuzz）、探听与地形 100% 一致、骰子分配 10368 种组合穷举、reducer 纯度与确定性。
- 组件层：骰子盘、探听按钮的禁用理由、快捷键派发。
- 回放：同种子同操作序列必须逐步哈希一致，改操作必须分叉。

## E2E 说明

`npm run test:e2e` 使用**系统已安装的 Chrome**（`channel: 'chrome'`），
不执行 `npx playwright install`，因此不会下载浏览器。若本机没有 Chrome，请改用 Edge：

```ts
// playwright.config.ts
channel: 'msedge',
```

## 已知取舍

| 项 | 阶段 0 的选择 |
|---|---|
| 网格拓扑 | 逻辑与视觉统一为 pointy-top 六边形，轴向坐标六向邻接，相邻格共享整条边 |
| 墙的呈现 | 墙以边线呈现而非整格；可见地板格一律按真实地形描墙线，因此**探听的信息价值下降**（只剩通路 / 异响与可落脚标记）。要收回这个取舍，把渲染模型里墙边的取值改为「仅当邻格已知为墙」即可，不影响其余渲染逻辑 |
| 移动点上限 | 不设上限，严格按设计文档 §3.2 的字面公式 |
| 锁骰 | 阶段 0 是空操作预留槽，HUD 明示「暂无用途」 |
| 探听结果 | 永久保留，不随回合过期 |
| 胜利条件 | 踏上出口格即胜（守卫 Boss 属阶段 1/2） |
