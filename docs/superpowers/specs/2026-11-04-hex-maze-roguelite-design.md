# 《迷雾迷径》产品规划文档

> 回合制 · 六边形网格迷宫探索 Roguelite
> 版本 v1.1 · 2026-11-04 · 状态：设计已确认，待实现计划

---

## 1. 概述

### 1.1 一句话定位

在一座完全漆黑、由墙体构成的迷宫里，你靠掷骰获取行动力、靠卡牌战斗与自保、靠气味判断怪物是否逼近，穿过奇遇与陷阱，击败守卫抵达对侧出口。

### 1.2 核心体验支柱

| 支柱 | 含义 | 支撑机制 |
|---|---|---|
| **黑暗中的推理** | 看不见，所以必须靠探听与记忆规划 | 纯黑迷雾 + 探听三态反馈 |
| **骰子的赌博** | 每回合的点数决定你这回合是爆发还是苟活 | 3d6 锁骰分配 |
| **嗅觉的追逐** | 怪物不是雷达，它循着你留下的气味走 | 气味场 + 三态追踪 |
| **资源紧张** | 你的卡是消耗品，打一张少一张 | 卡牌消耗品经济 + 奇遇补给 |

### 1.3 平台与技术形态

- **平台**：Web 浏览器优先（桌面端优先，兼顾移动窄屏）
- **前端**：React 18 + TypeScript + Canvas 2D + Zustand
- **后端**：轻量 Serverless 代理，仅用于转发 LLM 出题请求与隐藏 API Key
- **单局时长**：20–30 分钟
- **一局规模**：约 400–600 格的大型迷宫，10 张起始卡

## 2. 核心循环

```
┌──────────────────────────────────────────────────────┐
│  局外：解锁卡池 · 扩充起始牌数 · 调整起始配置          │
└───────────────────────────┬──────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────┐
│  局内：选 10 张牌 → 进入迷宫                          │
│                                                      │
│   ┌── 玩家回合 ─────────────────────────────┐       │
│   │ 掷 3d6 → 行动                            │       │
│   │  ├ 移动（消耗移动点）                    │       │
│   │  ├ 探听（消耗移动点，每回合限 2 次）      │       │
│   │  ├ 出牌（投入骰子）                      │       │
│   │  └ 结束回合                              │       │
│   └───────────────┬──────────────────────────┘       │
│                   ↓                                   │
│   ┌── 结算 ─────────────────────────────────┐       │
│   │ 气味更新 → 怪物行动（各掷 1d6）→ 感知更新  │       │
│   └───────────────┬──────────────────────────┘       │
│                   ↺ 回到玩家回合                       │
│                                                      │
│   途中：奇遇房 · 宝箱房 · 祭坛 · 商店 · 陷阱 · 战斗     │
└───────────────────────────┬──────────────────────────┘
                            ↓
                 击败出口守卫 → 抵达出口 → 胜利
```

## 3. 回合结构与骰子经济

### 3.1 回合流程

**玩家回合开始**
1. 递减 buff 时长（免伤类 buff 在本回合结束时才失效，保证覆盖完整回合）
2. 刷新怪物意图显示（图标 + 数字）
3. 掷 3 颗 d6

**行动阶段**（顺序自由，可反复进行，直到无合法行动或主动结束）

| 行动 | 消耗 | 说明 |
|---|---|---|
| 移动 1 格 | 1 移动点 | 沿相邻格移动；进入怪物所在格视为近战攻击（每回合限 1 次） |
| 探听 | 1 移动点 | 每回合限 2 次（可被卡牌提升） |
| 打出卡牌 | 投入一颗骰子 | 骰子不可拆分；**该骰面的点数必须尚未被移动花掉**（见 §3.2） |
| 结束回合 | — | 快捷键 `空格` |

**玩家回合结束**
1. 气味更新：玩家本回合走过的每格 +1
2. 怪物行动：每只怪物各掷 1d6，得到本回合移动步数，按其状态行动
3. 怪物感知更新：采样气味场，决定 `游荡 / 警觉 / 追击`
4. 全图气味 -1（下限 0）

### 3.2 锁骰规则

| 规则 | 定义 |
|---|---|
| 投掷 | 每回合固定 3 颗 d6，不主动重掷（卡牌可提供重掷） |
| 投入卡牌 | 骰子**不可拆分**，一张 `cost` 的卡需要一颗 `骰面 ≥ cost` 的骰子 |
| 一对一 | 一颗骰子只能投入一张卡 |
| 移动点 | **未投入卡牌的骰子，其面值的总和** = 可移动格数（1 点 = 1 格） |
| 花掉的点不能再用 | 投入/预留一颗骰子等价于花掉它的面值：要求 `已花点 + 骰面 ≤ 未预留骰面之和`。先把移动点走完再锁骰出牌是**非法**的，移动点不会变成负数 |
| 卡牌点数 | 卡牌 `cost` 范围 1–4 |

**示例**：掷出 5 / 4 / 1
- 方案 A：5 点骰 → cost 5 卡，4 点骰 → cost 4 卡，1 点骰 → 移动 1 格
- 方案 B：5 点骰 → cost 3 卡（浪费 2 点），其余 4+1 = 5 点移动
- 方案 C：三张卡（5→cost5，4→cost4，1→cost1），0 移动点，本回合完全放弃机动

> 设计意图：同一手骰子在不同分配下产出完全不同的回合，"点数决定行动力"因此包含**火力与机动的取舍**，而非单纯的总量换算。

### 3.3 速度平衡

| 角色 | 每回合移动期望 | 说明 |
|---|---|---|
| 玩家 | 3–6 格（实际） | 骰子总和期望 10.5，但多数骰子会被卡牌消耗 |
| 嗅犬 / 游魂 / 守卫 | 3.5 格 | 掷 1d6 作为步数 |
| 石卫 | 2 格 | 固定 1–3 步，移动慢 |
| 蛛巢 | 0 格 | 静止，以陷阱代替移动 |

玩家机动性约为游荡怪物的 1.5–2 倍，**足以周旋但没有余裕**。这是"能甩开但甩不掉"的基准手感。

## 4. 资源系统

| 资源 | 初始/上限 | 获取 | 消耗 |
|---|---|---|---|
| HP | 100 | 恢复类卡牌、休整房 | 受击、陷阱、答错惩罚 |
| 卡牌 | 10 张（可局外扩至 15） | 奇遇房、宝箱房、战斗掉落、商店 | 打出即消失（消耗品） |
| 行动点 | 每回合由骰子产生 | 掷骰 | 移动、探听、卡牌 |
| Buff | 带回合时限 | 卡牌、祭坛、奇遇房 | 时限到自动失效 |
| 气味 | 地图字段（玩家不直接可见） | 移动 | 每回合自然衰减，可被地形清除 |
| 碎片 | 0 | 击败怪物、奇遇房答对 | 商店买卡 / 升级 / 治疗 / 提示 |

> **MVP 范围**：碎片、商店、祭坛在阶段 3 之后实现。阶段 0–2 的唯一资源是卡牌 + HP。

### 4.1 状态效果

负面状态由陷阱房施加，可被「止血」卡清除。

| 状态 | 效果 | 持续 |
|---|---|---|
| 流血 | 每回合结束扣 3 HP | 3 回合 |
| 中毒 | 每回合结束扣 2 HP，且治疗效果减半 | 3 回合 |

Buff 与状态统一由 buff 生命周期模块管理（施加时记录剩余回合，回合结束递减，归零移除）。

### 4.2 陷阱（阶段 1）

| 项 | 规则 |
|---|---|
| 生成 | 关卡生成时按 `trapDensity`（默认 0.06 × 地面格数）布在地面格；起点、出口、距起点 < 3 格的格子不放 |
| 公平性 | **每个陷阱都必须可绕开**：把全部陷阱视为不可通行后，起点到出口仍必须可达 |
| 触发 | 玩家进入陷阱格时触发一次，随后该陷阱消耗；触发伤害 5 HP，并随机施加流血或中毒（各 50%） |
| 探听 | 含陷阱的相邻格返回 `通路（有异响）`，只提示「有东西」，不揭示类型 |
| 蛛巢 | 静止怪物，每回合结束时在相邻可走格布置陷阱；每回合最多新增 2 个，不覆盖已有陷阱、玩家脚下、起点与出口 |
| 清除 | 仅「止血」卡可移除流血 / 中毒（陷阱本身不可解除，只能绕开） |

> 数值先按上表落地，`npm run balance` 实测后再回调；调数值必须同步本节。

## 5. 迷雾、探听与气味

### 5.1 迷雾规则

- **未踏足的格子完全不可见**（纯黑，连墙体结构都不显示）
- 踏足过的格子**永久可见**（已探索区域常驻显示）
- 奇遇房门**自发光**：即使在纯黑迷雾中也保留一点微弱冷光，作为"附近有东西"的唯一视觉暗示

**房间例外（阶段 2 起）**

- 玩家**踏进房间房体的任一格**时，该房间矩形内所有可走格一次性标为已踏足：
  房型、边界墙、房内怪物与守卫立刻全部可见，不用逐格摸黑。
- 只对整个房间的房体生效，走廊与房外格子仍然遵循迷雾规则。
- 陷阱**不因此暴露**：陷阱本来就不渲染，玩家仍要靠探听「有异响」判断。
- 首次进入某房间时给一行日志（「你走进了战斗房」），房内地板按房型轻染色，
  让"我进房间了"这件事可感知；房间类型标签取自 `roomKindLabel`。
- 起点与出口位于房间外的边缘走廊格，因此"进入房间"的判定点仍是踩进房体。

### 5.2 探听机制

玩家在完全黑暗的迷宫里必须有主动获取信息的手段，否则导航退化为撞墙试错。

| 项 | 规则 |
|---|---|
| 成本 | 1 移动点 |
| 频次 | 每回合限 2 次（`探查术` 卡可临时 +3） |
| 范围 | 玩家所在格的**所有相邻格** |
| 返回 | 每个未踏足相邻格返回三态之一 |

**探听三态**

| 返回 | 含义 |
|---|---|
| `有墙` | 该方向不可通行 |
| `通路（安静）` | 可通行，且无异常 |
| `通路（有异响）` | 可通行，但内含陷阱 |

> 陷阱因此是**公平但需推理**的：你知道"那边有东西"，但不知道是什么、要不要赌。

### 5.3 气味规则

| 规则 | 定义 |
|---|---|
| 产生 | 玩家每移动 1 格，在**途经的每一格（含落点）**留下气味 +1 |
| 衰减 | 每回合结束全图 -1，下限 0 |
| 静止 | 玩家不动 → 该格气味不增长，但也不会立即消散（需等自然衰减） |
| 清除 | 特殊地形：玩家**落点结算时**（本格气味 +1 之后）立即把该格及相邻格气味归零 |

**特殊地形**：乱石堆、水渍、通风口。三类效果统一为"清除周围气味"，视觉上通过贴图区分。

**特殊地形落地口径（阶段 2）**

| 项 | 规则 |
|---|---|
| 密度 | 地面格数 / 80（沿用 §14），向下取整；46×30 地图约 5 个 |
| 布点 | 三类等概率随机；避开起点、出口、陷阱格与怪物布点格 |
| 触发 | 每次踏上该格都触发（含近战击杀后的落点），在气味 +1 之后立即清除，因此**本步留下的气味一并归零** |
| 效果 | 只影响气味，不改变通行性，也不做「陷阱可绕开」式的可达性校验 |
| 数据 | 存在 `Level.terrain`（格 → 地形类型）；**不新增 cell 值**，格子仍只有地板 / 墙两态 |

> 原文「下回合踩上时」有歧义，阶段 2 钉死为「踩上即清、含本步气味」：
> 否则玩家踩上去的那一格反而留着最新鲜的气味，清除等于无效。

### 5.4 感知判定

```
警觉：怪物的【感知半径】内，存在气味 ≥ 2 的格
      → 怪物获得玩家「最后已知位置」（该范围内气味最高的格），进入警觉

追击：怪物与玩家的距离 ≤ 2
      → 锁定玩家实时位置，进入追击
```

> 感知半径是"闻得到多远"，因此不同怪物对同一片气味有不同反应：石卫（半径 2）迟钝、游魂（半径 4）灵敏。距离与气味是两个独立维度，二者取交集才触发警觉。

## 6. 怪物系统

### 6.1 三态追踪

| 状态 | 行为 | 计入眼睛徽章 |
|---|---|---|
| **游荡** | 随机移动（走向随机可达格） | 否 |
| **警觉** | 朝气味最高的方向寻路；到达后原地搜索相邻几格 | 是 |
| **追击** | 锁定玩家实时位置，直线扑杀，每回合 1–6 步 | 是 |

### 6.2 追击解除条件（任一满足）

0. **预警**：怪物首次从游荡/警觉转入追击时，先预告 1 回合（显示"它发现你了"），该回合不移动不攻击 —— 玩家有一次反应窗口。结算顺序：发现发生在回合结束的感知阶段，该阶段只把意图改为「搜索」并标记预警；下一回合怪物仍不移动不攻击，再下一回合才正常行动。`eager` 性格（守卫）跳过预警。
1. 玩家进入**低气味区**（相邻格气味均 ≤ 1）并**静止 2 个回合** → 追击降级为警觉
2. 命中「驱散 / 致盲」类卡牌 → 直接降级为游荡，且 **2 个回合内不再感知**（`dazeTurns`）；否则同回合结束的感知会立刻把它重新锁回追击
3. 命中「定身」卡牌 → 本回合无法行动与感知（不改变状态，但打断锁定）。判定持续到本回合结算结束：不行动、不感知、不更新最后已知位置；回合末清除定身标记

> 三条解除路径保证"被锁定"是**危险但可解**的，而不是必死。缺乏解除手段的追击只会制造死亡螺旋。

### 6.3 意图显示

右上角**眼睛图标 + 角标**显示处于 `警觉 / 追击` 的怪物数量。悬停展开每只怪物的状态、意图与距离。

怪物格上方显示意图图标与数字：

| 意图 | 含义 |
|---|---|
| 👣 + N | 移动 N 格 |
| ⚔ + N | 攻击，伤害 N |
| 🔍 | 搜索 |
| ❄ | 被定身 |

> 攻击意图在结算时**复查距离**：若玩家在怪物行动前已离开相邻格，该次攻击落空（不造成伤害，也不会临时改成移动）。因此「读到 ⚔ 后先退一格」是有效应对。

玩家格周围显示攻击范围高亮。

### 6.4 怪物原型

| 怪物 | HP | 伤害 | 感知半径 | 移动 | 特点 |
|---|---|---|---|---|---|
| 嗅犬 | 20 | 4 | 3 | 1d6 | 快、追击积极，主要威胁 |
| 石卫 | 60 | 10 | 2 | 1–3 | 慢、高伤高血，适合教学 |
| 游魂 | 25 | 6 | 4 | 1d6 | **无视墙体移动**，压迫感来源，HP 低 |
| 蛛巢 | 30 | 3 | 2 | 静止 | 在周围布陷阱，考验路线规划 |
| **守卫（Boss）** | 100 | 8 | 全图（激活后） | 1d6 | 守在出口，三阶段 |

**守卫三阶段**
1. 冲击：每回合冲向玩家并重击
2. 召唤：召唤 2 只嗅犬，自身回血
3. 爆发：范围 AOE，需靠移动与卡牌规避

**守卫落地口径（阶段 2）** —— 数值为初值，按 `npm run balance` 回调，目标失败率见 §15（30%–50%）

| 项 | 规则 |
|---|---|
| 布点 | 出口房内、距出口 1 格的可走格（不占出口格、不与陷阱重叠）；**计入 `monsterBudget`** |
| 性格 | `eager`：跳过 §6.2 的预警回合；**未激活前只守在自己的位置**（意图恒为「搜索」，不循气味、不游荡）。**激活条件**：玩家踏进出口房任一格，或被玩家攻击；激活后感知半径全图，不会跟丢 |
| 阶段阈值 | HP ≤ 2/3 maxHp 进阶段 2，≤ 1/3 maxHp 进阶段 3；**只进不退**（回血不降级） |
| 阶段 1 冲击 | 沿用普通追击：1d6 步扑向玩家 + 8 点重击 |
| 阶段 2 召唤 | 进入阶段 2 的当回合**一次性**召唤 2 只嗅犬（守卫相邻的可走空格；不足则按可用格数召唤）并自身回 15 HP（不超过 maxHp）；召唤物当回合不行动（意图为搜索），下一回合起正常结算；**不计预算**、不会二次召唤，但计入眼睛徽章 |
| 阶段 3 爆发 | 每回合意图改为 AOE：半径 2、伤害 12，走 §6.5 伤害管线（可被闪避 / 免疫 / 减伤影响）；意图**提前一回合公开**，玩家可靠移动出圈规避 |
| 胜利门 | **守卫存活时踏上出口不判胜**，只给提示（日志 + notice 文案）；击杀守卫后踏出口才胜利。击杀瞬间玩家正站在出口格上的，立即判胜 |
| 演出 | 阶段切换 / 召唤 / AOE 各产出一个演出事件，复用既有闪光与飘字通道；**单次转移上限 1 个阶段事件 + 2 个召唤事件 + 1 个 AOE**，AOE 只发一个 `bossAoE`（不再叠加 `monsterAttacked`，避免重复飘字），串行时间轴不会因 Boss 回合拉长 |
| 档位 | `guardianTier` 本轮不分档，守卫数值固定为上表 |

### 6.5 战斗结算

```
最终伤害 = max(1, 卡牌伤害 - 目标防御值 - 目标减伤buff值)
```

- **玩家基础攻击力 = 8**（不依赖卡牌）。卡牌打空时仍可徒手攻击，这是没有资源时的兜底手段。
  （近战每回合限 1 次，见下；8 点是「一次挥击约等于一张低费攻击卡」的标定值）
- 玩家受击扣除 HP；HP ≤ 0 → 本局失败
- 防御类卡牌提供回合制减伤；`闪避` 可完全免伤一次
- 进入怪物所在格视为近战攻击（伤害 = 玩家基础攻击力 8），消耗 1 移动点
- **近战每回合最多 1 次**（阶段 2 起）：一回合的移动点很多，若每次 1 点都能挥一下，
  3d6 的一回合就能打出十倍于卡牌的伤害，卡牌体系会被直接架空。近战定位是「没牌时的兜底」，
  不是主要输出；主要输出仍然靠卡牌。次数在回合结束时重置。

## 7. 卡牌系统

### 7.1 通用结构

```
{ id, name, type, rarity, cost, effect, upgradeable }
```

- `type`：攻击 / 防御 / 恢复 / Buff / 功能
- `rarity`：普通 / 精良 / 史诗
- `cost`：1–4
- 卡牌是**消耗品**，打出即从牌库移除

### 7.2 初始卡池（普通）

| 名称 | 类型 | cost | 效果 |
|---|---|---|---|
| 挥击 | 攻击 | 1 | 造成 6 伤害 |
| 投石 | 攻击 | 2 | 造成 8 伤害（远程直线） |
| 重锤 | 攻击 | 3 | 造成 14 伤害，击退 1 格 |
| 铁壁 | 防御 | 2 | 本回合受到伤害 -4 |
| 闪避 | 防御 | 1 | 本回合首次受击完全免伤 |
| 药剂 | 恢复 | 2 | 回复 20 HP |
| 止血 | 恢复 | 1 | 移除流血 / 中毒 |
| 战意 | Buff | 2 | 接下来 3 回合伤害 +2 |
| 铁壁姿态 | Buff | 1 | 接下来 2 回合免疫伤害 |
| 疾行 | Buff | 1 | 接下来 2 回合额外移动点 +1 |
| 屏息 | 功能 | 2 | 清除相邻格气味，强制身边怪物降级为警觉 |
| 驱散 | 功能 | 3 | 指定怪物降级为游荡（打断追击） |

| 探查术 | 功能 | 1 | 本回合探听次数 +3 |
| 换骰 | 功能 | 1 | 弃掉 1 颗骰子并重掷 |

### 7.3 精良 / 史诗牌池

| 名称 | 稀有度 | 类型 | cost | 效果 |
|---|---|---|---|---|
| 破甲 | 精良 | 攻击 | 2 | 造成 10 伤害，无视 3 点防御 |
| 荆棘甲 | 精良 | 防御 | 2 | 本回合受到伤害 -4，且反弹 3 伤害 |
| 应急 | 精良 | 恢复 | 1 | 回复 8 HP，本回合结束再回复 8 |
| 战吼 | 精良 | Buff | 3 | 接下来 3 回合伤害 +3，行动点 +1 |
| 猎手直觉 | 精良 | 功能 | 2 | 揭示周围 2 格内所有怪物位置 |
| 处刑 | 史诗 | 攻击 | 4 | 造成 22 伤害；若目标 HP < 30% 则伤害翻倍 |
| 静滞力场 | 史诗 | 功能 | 3 | 半径 2 内所有怪物本回合无法移动与感知 |
| 循环 | 史诗 | 功能 | 2 | 回收 1 张已打出的卡到牌库 |
| 血契 | 史诗 | Buff | 3 | 接下来 4 回合伤害 +4，每回合流失 3 HP |

### 7.4 卡牌升级（祭坛 / 奇遇房）

升级 = 为一张卡附加一个 modifier。**同类 modifier 不可叠加**，不同类可叠加。

| modifier | 效果 |
|---|---|
| 精简 | `cost` -1 |
| 锋利 | 伤害 +2 |
| 广域 | 范围 +1 格 |
| 强化 | 数值类效果 +50%（向下取整） |
| 专精 | 附加专属效果（逐卡定义，例：`药剂` 改为同时清除 1 层负面状态） |

### 7.5 平衡约束

强力"破局卡"（驱散 / 定身 / 击退 / 静滞力场）受**双重约束**：消耗品数量有限 + 需要占用骰子点数。因此不会出现"永远有解"，但被锁定时确有翻盘手段。

### 7.6 战斗掉落（阶段 1）

- 击杀任意怪物后**必掉 1 张**普通卡，直接从掉落池抽入手中（不需要拾取交互）。
- 掉落池 = 15 张普通卡中**不在初始牌组**的 9 张；同名卡可重复获得。
- 手牌上限 **15 张**；达到上限后不再掉落（避免无限滚雪球）。
- 掉落使用局面 RNG（`GameState.rngState`），同种子同操作序列必须得到同一张卡。
- 阶段 2 的房间奖励（宝箱 / 战斗房 / 奇遇）在此之上扩展，不改动本条的保底掉落。

## 8. 房间与奇遇

### 8.1 房间类型

| 房间 | 进入时 | 产出 |
|---|---|---|
| 战斗房 | 强制遭遇 | 击败后掉随机卡（阶段 3 起额外掉碎片） |
| 陷阱房 | 踩到陷阱格 | 伤害 / 流血 / 中毒 / 召怪 |
| 宝箱房 | 交互 | 1 张卡 或 1 个 buff |
| 祭坛 | 交互 | 升级 1 张卡 |
| **奇遇房（Q&A）** | 交互 | 见 8.2 |
| 商店 | 交互 | 碎片换卡 / 治疗 |
| 休整房 | 交互 | 回血 + 锁定 1 张卡（防止之后被扣） |
| 出口房 | 守卫 | 胜利 |

> **阶段范围**：阶段 2 只实现 战斗房 / 陷阱房 / 宝箱房 / 奇遇房 / 休整房 / 出口房 六类；
> 祭坛与商店依赖碎片与卡牌升级，属阶段 3。

**房间分配算法（阶段 2）**

BSP 切出 9 个房间后按下列顺序打标签，全部随机性来自 `Rng32`：

| 步骤 | 规则 |
|---|---|
| 1 | 含起点的房间 = 起点房（无交互，安全区）；含出口的房间 = 出口房（守卫） |
| 2 | 从剩余房间选 **3** 个作奇遇房，**必须落在 3 个不同象限**（以地图中心划分四象限），且不是起终点房 |
| 3 | 再依次分配 宝箱房 1、休整房 1、战斗房 1、陷阱房 1 |
| 4 | 9 个房间正好用满（2 起终 + 3 奇遇 + 4 功能），不留随机房 |
| 门 | 每个房间记录一个 `door`：房间边界上接走廊的格中随机选 1 个，用于门标记与奇遇房冷光 |
| 战斗房 | 额外布 2 只嗅犬，**计入 `monsterBudget`**；玩家踏入该房任一格 → 房内怪物立即转追击且**跳过预警** |
| 陷阱房 | 房内陷阱密度 ×3（全局密度不变），仍受「每个陷阱可绕开」校验约束 |
| 结算 | 每个房间的交互与奖励**只结算一次**，状态记在 `GameState.roomStates`；重复交互被拒绝 |

> **为什么奇遇房是 3 间不是 2 间**：§8.2 的「连答 3 题」需要一局内至少 3 次答题机会，
> 而每次答题只来自一间奇遇房（每房固定一题、只结算一次）。2 间房会让连答奖励永远不可达。
> 因此阶段 2 定为 3 间奇遇房，分属 3 个不同象限，保证分散可发现。

> **交互的回合判定**：房间交互**不消耗移动点**。因此站在未结算的宝箱 / 休整房里时，
> 即使移动点已耗尽也视为「仍有合法动作」，不会触发自动结束回合（否则交互机会会被抢走）。
> 起点与出口落在房间外的边缘走廊格上，`roomIndexAt` 对这两格返回「不在房间内」——
> 起终点房本来就没有交互，房间标签只由房体矩形判定。

**房间产出数值（阶段 2 初值）**

| 房间 | 产出 |
|---|---|
| 宝箱房 | 50% 抽 1 张普通卡（走 §7.6 掉落池与手牌上限）/ 50% 给一个临时 buff（战意 / 铁壁姿态 / 疾行 等概率，持续回合沿用卡牌定义） |
| 休整房 | 回复 30 HP，并**随机锁定 1 张手牌**（`Rng32` 选，日志点名）；锁定存**卡牌 uid**，不存手牌下标（扣卡后下标会错位）；被锁定的卡在答错扣卡时豁免 |
| 战斗房 | 击杀掉落沿用 §7.6，不额外加码 |
| 陷阱房 | 沿用 §4.2 |
| 出口房 | 守卫见 §6.4，胜利门同上 |

> **可发现性补丁**：奇遇房门**自发光**（纯黑迷雾中留微弱冷光）；普通房间门不发光。奇遇因此是"黑暗迷宫里稀缺的一点光"，每次发现都有分量。陷阱房本身不发光，但其内部陷阱格通过探听返回"有异响"来预警，保证公平。

### 8.2 奇遇房（Q&A）流程

```
进入 → 同步出题（阶段 2 用内置题库，无 loading）→ 题目 + [对] [错] 按钮 + 可选 [提示]
                                        ↓
        答对 → 随机正面奖励：卡牌 / 回血 / 临时 buff（阶段 3 起追加碎片）
        答错 → 随机惩罚：损失 15% 最大 HP  或  随机失去 1 张卡（牌数保留下限 3）
```

| 规则 | 定义 |
|---|---|
| 题目 | 二选一（对 / 错）的事实性问题，中文 |
| 提示 | 消耗 1 张卡 → 显示该题的 `hint` 线索，**线索不含答案**；每题限一次。阶段 3 引入碎片后可改为花 1 碎片 |
| 连答 | 连续答对 3 题 → 额外抽 **2 张普通卡**（走 §7.6 掉落池与手牌上限），随后连答计数归零 |
| 惩罚随机 | 答错时在「扣血」与「扣卡」之间随机二选一，避免玩家被单一惩罚卡死 |
| 扣卡下限 | 手牌 ≤ 3 张时不再扣卡，惩罚强制改为扣血；休整房锁定的卡豁免 |
| 一次性 | 每房首次交互即固定题目，**每房只结算一次**；结算后再次交互被拒绝 |
| 答题与回合 | 答题期间视为「仍有合法动作」，**不触发自动结束回合**；答题本身不消耗移动点 |

**答对奖励数值（阶段 2 初值）**：等概率三选一 —— 抽 1 张普通卡 / 回复 20 HP / 一个临时 buff（战意 / 铁壁姿态 / 疾行）。

> **两处取舍（原文自相矛盾，阶段 2 裁决）**
> 1. 原文「提示 = 排除一个选项」在二选一题目下等于直接公布答案，提示会变成无脑最优解。
>    改为「消耗 1 卡换一条不含答案的线索」，题目数据结构因此增加 `hint` 字段。
> 2. 原文「连答奖励 1 张精良及以上卡牌」与阶段 2 只有 15 张普通卡池冲突（精良 / 史诗属阶段 3）。
>    改为额外抽 2 张普通卡，手牌上限 15 自然封顶。

### 8.3 LLM 出题链路（阶段 2 不实现，保留为后续接口契约）

> **阶段 2 口径**：题目全部来自内置题库（`src/rules/encounter/questions.ts`，静态数据、同步出题、无网络），
> 因此不存在 loading、超时与降级。本节描述的代理链路整体后置，`server/`、`shared/`、`src/llm/` 本轮不建。
>
> **注入缝（本轮就要留）**：新增 `setQuestionBank` intent，store 侧 `injectQuestions()` 是唯一入口；
> 规则层对注入条目做 schema 过滤（`question` ≤ 60 字、`answer` 为布尔、`hint` 非空、`id` 唯一），非法条目被丢弃。
> 以后接 LLM 时只在 store 侧加异步 fetch，**`rules/` 永不碰网络**，答题结算仍在纯 reducer 内完成，保证可复现。

**请求 → 校验 → 重试 → 兜底**

```
客户端 → POST /api/question { difficulty, topic, seed }
            ↓
        服务端构造 prompt（含出题硬约束）
            ↓
        调用 LLM，要求严格 JSON 输出
            ↓
        JSON Schema 校验
        ├─ 通过 → 返回题目
        └─ 失败 → 重试（最多 2 次）
              └─ 仍失败 → 降级到内置题库（服务端静态题库，按难度分级）
```

**出题 prompt 硬约束**
- 单一确定答案，不存在歧义或多解
- 常识或已公开知识可验证
- 不涉及争议话题、时效性事实、具体日期 / 版本号 / 人名
- 中文表述，长度 ≤ 60 字
- 不给出"以下哪个"式的多选题

**题目 schema**（阶段 2 增 `id` 与 `hint`；题目必须是可判对错的陈述句，不是疑问句）

```json
{
  "id": "astro-001",
  "question": "地球围绕太阳公转。",
  "answer": true,
  "hint": "它的轨道周期约等于一个回归年。",
  "difficulty": "easy",
  "topic": "天文"
}
```

**降级策略**（后续接 LLM 时生效）：LLM 超时（8s）/ 校验失败 / 服务不可用 → 立即使用内置题库，保证玩家永远不卡在 loading。
阶段 2 没有 LLM，内置题库就是唯一来源，因此该降级路径天然满足。

## 9. 关卡生成

### 9.1 生成流程

```
1. BSP 划分      → 9 个不规则房间区域（阶段 2）
2. 走廊生成      → 生成树保证全连通
3. 墙增广        → 在房间区域内挖出迷宫结构
4. 造环          → 随机移除约 18% 的墙，形成环路
5. 剪死路        → 迭代删除度数 1 的地面格至不动点（阶段 2 验收要求无死路）
6. 房间标签      → 按 §8.1 分配算法打 kind 与 door
7. 布点          → 出口在入口对边；守卫守出口（计入预算）
                    怪物按难度分布（距入口 ≥ 8 格），战斗房额外 2 只
                    奇遇房 = 2（分散不同象限）；商店 / 祭坛属阶段 3
                    陷阱按密度随机（陷阱房内 ×3）
                    特殊地形按 §5.3 密度随机
8. 校验          → 连通性 / 无孤岛 / 无死路 / 入口→出口最短路 ≥ 60 格
                    / 陷阱不堵唯一通路 / 守卫距出口 ≤ 2 / 奇遇房异象限
```

### 9.2 关键约束

| 约束 | 原因 |
|---|---|
| 迷宫必须**有环** | 纯树状迷宫只有唯一解，玩家无"绕路"策略可言 |
| 出口在入口**对边** | 保证单局路径长度与 20–30 分钟时长 |
| 怪物距入口 ≥ 8 格 | 开局安全期，让玩家先熟悉探听与骰子 |
| 陷阱不堵唯一通路 | 避免出现必死格 |
| 奇遇房 ≥ 2 且分散 | 保证 Q&A 是核心体验而非可选项 |
| 种子化 RNG | 同 seed 完全可复现 → 便于测试、分享挑战、定位 bug |

### 9.3 难度参数

```ts
interface Difficulty {
  mazeWidth: number;      // 阶段 2 默认 46（阶段 1 为 34）
  mazeHeight: number;     // 阶段 2 默认 30（阶段 1 为 24）
  roomCount: number;      // 阶段 2 默认 9（阶段 1 为 7）
  monsterBudget: number;  // 阶段 2 默认 10 = 1 守卫 + 2 战斗房嗅犬 + 7 游荡
  trapDensity: number;    // 默认 0.06（陷阱房内 ×3）
  minPath: number;        // 阶段 2 默认 60（阶段 1 为 20）
  loopRatio: number;      // 默认 0.18，不随尺寸变
  guardianTier: number;   // 守卫强度档位；阶段 2 固定单档，数值见 §6.4
}
```

> 扩图依据：46×30 / 9 房 / minPath 60 经 1000 seed 实测零失败，最短路 60–104 步、填充率 0.255–0.351（均值 0.305，仍在 25%–55% 内）。
> **不要靠降 `loopRatio` 拉长路径**：实测降到 0.06 时填充率跌破下限。数据见 `docs/balance/phase2-content.md`。

### 9.4 BSP 落地细则（阶段 1 → 阶段 2）

阶段 0 的「主走廊 + 支路 + 捷径」是占位算法，阶段 1 按 §9.1 改为 BSP；阶段 2 在此基础上扩图并补齐布点：

| 项 | 落地口径 |
|---|---|
| 尺寸 | **46×30**，内区 44×28，最外圈恒为墙（阶段 1 为 34×24） |
| 房间 | BSP 递归切分到 **9** 个叶子；每个叶子 inset 1 后挖成房间，最小 3×3 |
| 走廊 | 生成树连接相邻子树；宽 1 格，按**轴向邻接**逐格挖（不能用 offset 的行列直走） |
| 墙增广 | 房间内部按约 0.2 的概率回填墙，制造房间内的迷路感；每次回填后用房间内 BFS 验证连通，断连即回滚 |
| 造环 | 候选 = 内区且已有 ≥2 个地面邻居的墙格；随机拆掉候选总数的 18% |
| 起点 / 出口 | 起点固定 `col=1`，出口固定 `col=W-2`；用走廊接进最近的房间 |
| 死路 | **阶段 2 剪除至 0**：造环后迭代删除度数 1 的地面格至不动点，再由校验拦截。死路格不在最短路上、删除不断连；剪除在布点与最短路计算之前完成 |
| 怪物组合 | **10 只 = 1 守卫（出口房）+ 2 嗅犬（战斗房）+ 7 游荡**；游荡部分沿用 50% 嗅犬 / 20% 石卫 / 15% 游魂 / 15% 蛛巢；距起点 ≥8，不放在出口与陷阱上 |
| 特殊地形 | 地面格数 / 80，三类等概率，避开起点 / 出口 / 陷阱 / 怪物布点（§5.3） |
| 校验 | 连通 / 无孤岛 / **无死路** / 环 ≥2 / 最短路 **≥60** / 每个陷阱可绕开 / 房间数 6–9 / 地面填充率 0.25–0.55 / **怪物数 === 预算（含守卫）** / **守卫距出口 ≤2** / **奇遇房 2 个且异象限** |
| 重试 | 校验失败换 `seed + attempt` 重试，上限 **24**（阶段 1 为 16；扩图后实测最大重试 12 次、均值 1.72）。分享与复现以 `level.seed` 为准 |
| 可复现 | 全部随机性来自 `Rng32`；同 seed 必须得到逐格相同的地图 |

> BSP 改造与本轮扩图都会让旧种子地图全部失效，这是预期行为；平衡数据必须重跑。
> 填充率阈值**不动**：扩图后实测最小 0.255，仍在 25%–55% 内；若后续 fuzz 出现越界再调，不要预先放宽。

### 11.1 目录结构

```
src/
  rules/                纯 TS，零 DOM 依赖，可注入 RNG

    combat/             伤害与防御结算
    buffs/              buff 生命周期
    monsters/           三态状态机 · 气味感知 · 意图生成 · 守卫三阶段
    fog/                迷雾可见性 · 探听 · 气味场
    traps/              陷阱触发与流血 / 中毒
    rooms/              房间查询与交互合法性（阶段 2）
    encounter/          奇遇房题库与答题结算（阶段 2，纯函数、无网络）
    turn/               回合状态机（纯 reducer）
    generation/         关卡生成与校验
    game/               开局构造
  core/                 可序列化 RNG · 意图时间线
  sim/                  平衡模拟（驱动 reduceGame）· 快照哈希 · 回放确定性
  state/                Zustand store（唯一调用 reduceGame 的地方）
  render/               three.js 2.5D 场景 + Canvas 贴片 · 演出时间轴（只读 state）
  ui/                   React 组件（HUD · 手牌 · 答题面板）
  llm/                  【后置】题目客户端（含降级与缓存）
server/                 【后置，阶段 2 不建】
  api/question.ts       LLM 代理（Schema 校验 · 重试 · 题库兜底 · 缓存）
shared/                 【后置】前后端共享类型（题目 schema · 错误码）
```

> 阶段 2 的题库是 `src/rules/encounter/questions.ts` 里的静态数据，不建 `server/content/questions.ts`；
> 接 LLM 时再把题库搬去服务端并启用上面三个后置目录。

### 11.2 架构铁律

1. `rules/` 全部为**纯函数**且可注入 RNG → 可单测、可回放、可复现
2. `render/` **只读** state，不含任何规则判断
3. `ui/` 只向 store 派发**意图（intent）**，不直接修改状态
4. 规则层不依赖 React / DOM / 网络，可独立在 Node 下运行

### 11.3 状态流

```
UI 事件 → dispatch(intent) → store 调 rules 纯函数 → 新 state
                                                     ↓
                                            render 层重绘（rAF 合并）
```

### 阶段 0 · 可玩骨架

**目标**：能在一座纯黑迷宫里，靠探听找到出口。

**范围**
- 六边形格渲染、墙以边线呈现、可落脚邻居高亮、缩放与拖动
- 迷雾：未踏足纯黑、踏足永久可见

**验收**
- [ ] 玩家能在无任何可见信息下，借助探听规划路线抵达出口

**可延后**：特效、动画、音效、局外系统

#### 视觉规格 v2.0（three.js 2.5D）

> 美术参考图与逐项比对图见 [`docs/visuals/`](../../visuals/README.md)。参考图只作方向对齐，不进入构建产物。
> 生成素材的 ImageGen prompt 归档在 [`docs/visuals/prompts/`](../../visuals/prompts/)。
> v1.2 中所有**信息可见性**约定（未探索纯黑、已探索永久可见、探听通路压暗、高亮只给已知可落脚、
> 墙不占格）在 2.5D 下全部保留，变的只是「怎么画」。

| 元素 | 规格 |
|---|---|
| 相机 | 正交相机固定俯角 **55°**（调参带 50–60°）。地面布局取「拉伸嵌入」：世界 `z = 逻辑y / sin(55°)`，使屏幕 x/y 与逻辑坐标精确相等，六边形在屏幕上仍是规整 pointy-top，现有拾取与镜头数学全部沿用 |
| 地块 | 六棱柱石台（顶面 + 朝向观察者的侧壁），albedo 与法线贴图来自生成素材管线；不抠背的素材居中裁方、满幅可平铺，避免平铺接缝落在格心上；每格固定色差保留 |
| 光照 | 片元内两项：**提灯项**（逻辑空间内到玩家的距离衰减，屏幕上保持圆形）与**记忆项**（已探索格的静态亮度，恒显著暗于提灯区）；取两者较大值。未探索格不发射任何几何，**唯一例外是奇遇房门冷光**（见下） |
| 阴影 | v1 **不用阴影贴图**（拉伸嵌入下阴影会沿 z 被拉长）；纵深由法线凹凸、两项光照、实体脚下的接触阴影贴片与 billboard 视差表达 |
| 墙 | 共享边上的低矮边脊（instanced 盒），高度低于实体脚锚；亮度仍随提灯距离衰减。不占格，语义与 v1.2 一致 |
| 实体 | 玩家与怪物为面向相机的 billboard sprite（生成素材 + alpha，素材未就位前回退程序化字形），脚锚在格心；受击闪白、消散、命中用材质 uniform 表达，不做逐帧动画。sprite 乘同一提灯衰减，暗区不发光 |
| 记号与演出 | 血条、意图图标、出口记号、heard 记号为 Canvas 纹理贴片；伤害飘字 / 命中闪光 / 远程弹道取自演出时间轴（PresentationFrame），颜色与双编码沿用 palette |
| 房间标记 | 已探索房间的 `door` 格上放一枚程序化 Canvas glyph 区分类型（宝箱 / 休整 / 战斗 / 陷阱 / 出口），图标 + 颜色双编码，沿用 palette；不新增 ImageGen 素材 |
| 房型染色 | 房内地板按房型做低强度色偏（战斗偏红、休整偏绿、宝箱偏金、陷阱偏紫、奇遇偏青），走地板实例属性；与特殊地形纹理叠加，只影响观感，不参与规则 |
| 特殊地形 | 乱石 / 水渍 / 风口靠地板实例属性 + 程序化贴图区分，**不新增 cell 值**；只在已探索格显示 |
| 奇遇房门冷光 | 未探索区也发射的**唯一**几何：一枚程序化 Canvas glyph，不画地板、不受提灯衰减、亮度恒定微弱；每房恰好 1 枚，落在 `door` 上 |
| Boss 血条 | 守卫血量走 UI 顶栏长条（复用 HP 双条样式），不挤在实体头顶；阶段切换用既有闪光 + 飘字通道，并额外给一条顶部文字横幅（「守卫进入阶段 2 · 召唤」），保证阶段变化可感知 |
| 实例容量 | 地板 / 墙容量常量**不随扩图改动**：实例只来自已知格，46×30 实测峰值 485 / 882，远低于 1024 / 4096；加断言兜住未来扩图 |

> **取舍记录（沿用 v1.2）**：墙线对可见地板格一律按真实地形绘制，玩家因此能直接读出已探索区的邻接关系，
> 探听的信息价值下降，只保留「通路 / 异响」与「标记可落脚」的增量。
> 后续阶段用异响、陷阱预警承担信息增量；若要收回该取舍，把渲染模型里墙边的取值
> 改为「仅当邻格已知为墙」即可，不影响其余渲染逻辑。
>
> 墙的亮度随提灯距离衰减，是为了让远处墙体保持暗色、不通过亮度读出未探明区的地形；
> 这与上一条「真实地形直绘」并存，同属已知的泄露面，收回方式同样是改墙边取值那一处。

### 阶段 2 · 内容与奇遇

**目标**：能完整通关一局，20–30 分钟，有起承转合。

**范围**
- 扩图：46×30 / 9 房间 / minPath 60 / 怪物预算 10，剪死路至 0（§9.3、§9.4）
- 房间系统：战斗房 / 陷阱房 / 宝箱房 / 奇遇房 / 休整房 / 出口房，含分配算法与一次性结算（§8.1）
- 奇遇房 Q&A：**内置题库版**（同步出题、无网络）+ 提示线索 + 连答奖励 + 奖惩结算（§8.2）；
  留 `setQuestionBank` 注入缝，LLM 代理链路整体后置（§8.3）
- 守卫 Boss 三阶段与胜利门（§6.4）
- 特殊地形（乱石 / 水渍 / 风口）与气味清除（§5.3）
- **平衡模拟重写**：改为驱动 `createGame` + `reduceGame`，让卡牌效果与掉落真正进入模拟；
  这是房间与 Boss 数值调参的前提，必须先于内容落地拿到新地图基线

**局长换算口径**：按 25–30 秒/回合估算，20–30 分钟对应 **48–72 回合**。回合预算分配：

| 环节 | 目标回合 |
|---|---|
| 探索与找路 | 25 |
| 房间交互与 Q&A | 12 |
| 守卫战 | 15 |
| 脱追与周旋 | 8 |

> **这张表算的是真人，不是全图视野的模拟策略。** 46×30 实测平均移动点 10.52/回合、平均最短路
> 66.5 格，因此「知道出口在哪、沿最短路直奔」的 oracle 策略只需 **7 回合**。要让 oracle 跑到 48 回合
> 需要最短路 457 格，而整张图只有 433 个地面格（106%）—— **靠加 `minPath` 永远不可能达标**。
> 缺的不是地图尺度，是**迷雾下的找路成本**：出口只有踏足后才可见（`render/scene/plan.ts`），
> UI 无指南针，探听一次只揭示六邻格，玩家唯一的方向先验是「出口在入口对边」（§9.2）。

**因此模拟分两类策略，验收只挂迷雾受限策略**：

| 策略 | 信息量 | 用途 |
|---|---|---|
| `run` / `fight` / `escape` | **oracle**：全图 A*，知道出口与所有怪物位置 | 机动性与卡牌强度的**下界**对照，不承担局长验收 |
| `explore` | **迷雾受限**：只走 `fog.visited` ∪ 探听到的通路格；躲开听到的陷阱（`passage_noisy`）；怪物可见性同 `render/model.ts`（踏足格，或警觉/追击且距离 ≤ `MONSTER_SIGHT`）；找不到已知出口时朝「右边缘」先验推进最近的前沿格 | 局长验收的主指标，也是真人承伤的近似 |

> `explore` 的已知局限：不消费房间交互与 Q&A（M3/M5 落地后补），也不模拟真人犹豫与误操作，
> 所以它仍是**下界**；最终判据是人工完整通关一局的实测耗时。
> 实测不达标时调 `minPath`、密度与内容量，**不要反向放宽验收标准**。

**验收**
- [ ] Q&A 房用内置题库**同步**出题，无网络请求、无 loading，玩法不中断
- [ ] `setQuestionBank` 注入的非法题目（超长 / 非布尔 / 缺 hint / 重复 id）被规则层拦下
- [ ] 一局完整通关耗时落在 20–30 分钟区间：**`explore` 策略** avgTurns 落 48–72，且人工实测一局确认；
      oracle 三策略（`run`/`fight`/`escape`）只作下界对照，不承担本条
- [ ] 关卡生成器对 1000 个随机 seed 均通过 `generateValidLevel`（连通 / 无孤岛 / **无死路** / 最短路 ≥60 / 陷阱可绕开 / 守卫与奇遇房布点约束）
- [ ] 守卫存活时踏出口不判胜，击杀后才胜利；守卫战失败率落在 §15 的 30%–50%
- [ ] 平衡模拟与游戏共用同一条规则路径，卡牌使用分布与强度有数据（`docs/balance/phase2-content.md`）
- [ ] 平均承伤仍在 20–60 目标带内（§14 的上下界），以 `explore` 为准

**可延后**：商店、祭坛升级、碎片经济、精良 / 史诗卡池、LLM 出题链路、美术阶段 B/C

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 完全黑地图导致挫败 | 玩家早期流失 | 探听 + 三态提示 + 奇遇门冷光 + 陷阱异响预警 + 阶段 4 新手引导 |
| 墙线按真实地形绘制导致探听贬值 | 玩家不再需要探听即可读出邻接关系，「黑暗中的推理」被削弱 | 已确认接受：探听聚焦「通路 / 异响」与可落脚标记；阶段 1 起由异响与陷阱预警承担信息增量 |
| LLM 出题质量不稳定 / 延迟高 / 失败 | Q&A 房体验断裂 | Schema 校验 + 重试 + 题库兜底 + 8s 超时降级 + 难度分级 |
| 追击锁死形成死亡螺旋 | 玩家无解感 | 玩家机动 ×1.5–2 + 静止降级 + 破局卡 + 追击首次触发有 1 回合预警 |
| 探索感与可解性失衡 | 迷宮变成枯燥的撞墙 | 埋点分析迷路时长与死亡点，参数化调探听成本与雾气衰减 |
| 资源过紧导致中后期无牌可用 | 战斗退化为纯走位 | 奇遇房 ≥ 2 + 宝箱补给 + 商店补货；监测"回合末牌数"分布 |
| 单局时长偏离目标 | 影响留存 | 生成参数化难度 + 埋点统计实际时长，反向调 `mazeWidth` / 怪物预算 |
| Web 优先但 LLM 需服务端 | 部署复杂度 | 仅一个 Serverless 端点；前端对题目接口做适配层，将来可换供应商 |

## 14. 待验证项（已有默认策略，按数据调整）

| 项 | 默认值 | 验证方式 | 调整触发条件 |
|---|---|---|---|
| 骰子数量 | 3 颗 d6 | 埋点统计每回合卡牌打出数 | 若平均打出 > 2.5 张卡 → 骰子不足，考虑 4 颗 |
| 探听频次上限 | 2 次/回合 | 统计每回合探听次数 | 若平均 < 0.5 次 → 成本过高，放宽为 3 |
| 玩家 HP | 100 | 统计平均承伤与死亡点 | 若平均承伤 > 60 → HP 偏高或怪物伤害偏高 |
| 追击脱离静止回合数 | 2 回合 | 统计追击成功率与脱离成功率 | 若脱离率 > 70% → 惩罚过轻 |
| 特殊地形密度 | 地面格数 / 80（46×30 约 5 个） | 统计玩家踩中率 | 若极少被使用 → 提示不足，增加视觉引导 |
| 怪物数量 | 10（1 守卫 + 2 战斗房 + 7 游荡） | 统计单局遭遇次数 | 若 > 25 次 → 遭遇过密，降低密度 |
| 地图尺度与局长 | 46×30 / minPath 60 → `explore` 目标 48–72 回合 | `explore` avgTurns + 人工实测耗时 | 若 < 48 回合 → 加内容密度或提 minPath；若 > 72 → 反向降。**oracle avgTurns 不是本项指标**（全图直奔只需 7 回合，见 §12 阶段 2） |
| 威胁强度 | 无下界 | 统计平均承伤 | 若 < 20 → 怪物只是装饰品，要加密度或伤害 |
| 守卫三阶段复杂度 | 三阶段 | 观察玩家在守卫战失败率 | 若 > 70% 失败 → 减少阶段或降低 AOE 范围 |

## 16. 术语表
